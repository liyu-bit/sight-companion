## 1. 接口契约（唯一的数据通道）

### HTTP 接口（A ↔ B-1 对接）

```
POST /api/advise

请求体：
{
  "image": "<纯 base64 字符串，不带 data:image/... 前缀>",
  "user": {
    "allergies": [{"name": "乳糖", "severity": "mild"}]
  }
}

响应体（B-2 定义的 JSON，另加 audio 字段）：
{
  "product": "某品牌纯牛奶",
  "expiry_days": 3,
  "allergen_hit": "乳糖",
  "price": "5.00",
  "advice": "建议换一盒",
  "reason": "还有 3 天过期，且你乳糖不耐受",
  "options": ["换一盒无乳糖牛奶", "这盒尽快喝完"],
  "user_decides": true,
  "speech": "这盒牛奶还有 3 天过期，你乳糖不耐受，建议换一盒；要不要听听别的选项？",
  "audio": "<音频 base64 或可播放 URL，B-1 填>"
}
```

### Python 函数签名（B-1 ↔ B-2 对接）

```python
# agents/advise.py 里，B-2 必须提供这个签名，B-1 只按这个调：
def advise(image_base64: str, user: dict) -> dict:
    """返回上面那个 JSON（不含 audio 字段）"""
    ...
```

### 图片格式（A ↔ B-1 对接，最容易翻车）

- A 传的是**纯 base64**，**不带** `data:image/jpeg;base64,` 前缀。
- B-1 解析时**不要再 strip 前缀**，直接当纯 base64 用。

## 2. 字段红线（谁都不许碰）

- **绝不允许出现**：`verdict` / `能买` / `别买` / `必须买` / `不能买` 这类替人拍板的字段或说法。
- 输出只有：`advice`（建议）+ `reason`（理由）+ `options`（给用户的选择）+ `user_decides: true`（决策权归使用者）。
- `user_decides` 恒为 `true`。

### 话术模板（三种场景）

| 场景 | 说法 | 不说 |
|---|---|---|
| 过敏命中（品类先验） | 「这是纯牛奶，你乳糖不耐受，**建议换一盒**无乳糖的。」 | 「别买」 |
| 临期 | 「这盒还有 3 天过期，**建议换一盒**，要不要听听别的选项？」 | 「别买」 |

| 信息不足 | 「没看清，**建议让家人帮你看一眼**，你自己定。」 | 「不知道」 |

## 3.5 信息获取策略（风险分级双轨制，2026-11-22 定稿）

**物理约束**：货架上的盒装牛奶，价格在正面、配料表在侧面/背面、生产日期在顶部封口。视障用户不能拿起商品翻转，一张照片物理上拍不全三样。所以**不追求信息齐全，追求在信息不全时给出有价值的「能不能买」建议**。

**核心：按过敏后果严重性分两条轨**（不是所有过敏原同等对待）：

| 轨道 | 类型 | 判断方式 | 读不到配料表时 |
|---|---|---|---|
| 非致命不耐受 | 乳糖不耐受、麸质轻症等 | **品类先验**（认出纯牛奶/酸奶→乳糖），不读配料表 | 照常给建议（误判不致命） |
| 致命过敏 | 花生、坚果、甲壳类、鱼类、牛奶蛋白、鸡蛋、大豆、小麦 | **必须读配料表**（含「可能含微量/交叉污染」） | **触发求助家属 Agent**，绝不判「安全」 |

**severity 字段**：`user.allergies` 每项带 `severity`（`mild`=非致命→品类先验；`severe`=致命→读配料表+求助）。MVP 阶段 demo 用 `mild`（乳糖），`severe` 轨在 C 阶段落地。

**决策优先级**（从高到低）：
1. **致命过敏**（刚性，不可漏判）→ 读配料表；读不到 → 求助家属。
2. **非致命不耐受** → 品类先验，认出品类即判断。
3. **临期** → 日期在顶部封口，俯拍作为**可选补充**。
4. **价格** → 正面，一张照能读。

**实现**：非致命轨用「品类→过敏」映射表做本地判断（C 阶段做成 RAG，引用权威来源如《中国食物成分表》）；致命轨读配料表，读不到/读不清触发求助家属，绝不给「安全」结论。`recognize.py` 输出需包含「品类」。

**商品库定位**：不是「补全信息的地基」（日期批次级、SKU 海量易变，补不全），而是「品类先验 RAG 背书」。
