## 1. 接口契约（唯一的数据通道）

### HTTP 接口（A ↔ B-1 对接）

```
POST /api/advise

请求体：
{
  "image": "<纯 base64 字符串，不带 data:image/... 前缀>",
  "user": {
    "allergies": ["乳糖"]
  }
}

响应体（B-2 定义的 JSON，另加 audio 字段）：
{
  "product": "某品牌纯牛奶",
  "expiry_days": 3,
  "allergen_hit": "乳糖",
  "price": "5.00",
  "advice": "建议换一盒",
  "reason": "还有 3 天过期，且你乳糖不耐受",
  "options": ["换一盒无乳糖牛奶", "这盒尽快喝完"],
  "user_decides": true,
  "speech": "这盒牛奶还有 3 天过期，你乳糖不耐受，建议换一盒；要不要听听别的选项？",
  "audio": "<音频 base64 或可播放 URL，B-1 填>"
}
```

### Python 函数签名（B-1 ↔ B-2 对接）

```python
# agents/advise.py 里，B-2 必须提供这个签名，B-1 只按这个调：
def advise(image_base64: str, user: dict) -> dict:
    """返回上面那个 JSON（不含 audio 字段）"""
    ...
```

### 图片格式（A ↔ B-1 对接，最容易翻车）

- A 传的是**纯 base64**，**不带** `data:image/jpeg;base64,` 前缀。
- B-1 解析时**不要再 strip 前缀**，直接当纯 base64 用。

---

## 2. 字段红线（谁都不许碰）

- **绝不允许出现**：`verdict` / `能买` / `别买` / `必须买` / `不能买` 这类替人拍板的字段或说法。
- 输出只有：`advice`（建议）+ `reason`（理由）+ `options`（给用户的选择）+ `user_decides: true`（决策权归使用者）。
- `user_decides` 恒为 `true`。

## 3. 演示设定（统一，别各设一套）

| 项 | 固定值 |
|---|---|
| 用户档案 | 乳糖不耐受（`allergies: ["乳糖"]`） |
| 演示商品 | 某品牌纯牛奶，保质期剩 3 天 |
| 演示台词（锁死） | **「这盒牛奶还有 3 天过期，你乳糖不耐受，建议换一盒；要不要听听别的选项？」** |

三人所有调优都朝这句台词对齐。

### 话术模板（三种场景）

| 场景 | 说法 | 不说 |
|---|---|---|
| 有风险 | 「还有 3 天过期、你乳糖不耐受，**建议换一盒**，要不要听听别的选项？」 | 「别买」 |
| 无明显问题 | 「没看到过期或过敏风险，**可以考虑这盒**，最终你决定。」 | 「能买」 |
| 信息不足 | 「没看清保质期，**建议让家人帮你看一眼**，你自己定。」 | 「不知道」 |
